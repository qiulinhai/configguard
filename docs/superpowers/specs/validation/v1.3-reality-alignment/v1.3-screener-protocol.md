## 0. Why This Screener Is Different

**Old screener goal:** "Find qualified users"
**New screener goal:** "Map population to F-type distribution"

This is a measurement instrument, not a filter. Every question is designed to produce a F-type signal, not a pass/fail.

## 1. Screener Questions v1.3

### Q1: Primary Workflow (Forced Segmentation)

**Question:** "Which best describes your primary config security work?"

```
A. Compliance / audit mapping (CIS, NIST, SOC2, ISO)
B. CI/CD pipeline security (GitHub Actions, Jenkins, GitLab)
C. Manual CLI / SSH config review
D. Security monitoring / runtime detection
E. Multi-vendor / platform management
```

**F-type Mapping:**
- A → F5 (Auditor) with high confidence
- B → F2/F1 (Operator) with high confidence
- C → F6 (Feature extractor) or F4 (Skeptic)
- D → F4 (Methodology doubt) or F3 (Silent)
- E → F1/F7 (Pragmatist) with high confidence

**Confidence:** A/B/E = 0.8+, C/D = 0.5 (more ambiguous)

---

### Q2: Failure Signal Extraction

**Question:** "Where do config security issues usually get caught in your org?"

```
a. Pre-deploy (in CI/CD pipeline)
b. Post-deploy (monitoring/alerting)
c. Audit cycles (monthly/quarterly)
d. Manual review (SSH/CLI)
e. Currently not detected / we find out reactively
```

**F-type Mapping:**
- a → F1 (Ecosystem, already has tooling)
- b → F4 (Detection mindset, will question methodology)
- c → F5 (Compliance workflow)
- d → F6 (Single feature interest) or F4
- e → F2 (Workflow inertia) or F3 (Silent — no detection at all)

---

### Q3: System of Record (Critical for F7 Detection)

**Question:** "If a config issue is found, where does it end up?"

```
1. Jira ticket
2. ServiceNow CMDB
3. Spreadsheet / email
4. Pipeline blocked / build failed
5. Ignored / informal fix
6. Other [free text]
```

**F-type Mapping:**
- 1, 2 → F7 (Political buy-in required, has formal process)
- 3 → F2 (Manual, process exists but weak)
- 4 → F1 (CI/CD integration exists)
- 5 → F3 (Silent) or F2 (Inertia)
- 6 → Probe deeper

**Critical:** Q3 is the strongest F7 predictor. "Ignored" + no formal process = highest inertia risk.

---

### Q4: Tooling Depth Check

**Question:** "Which tools are already part of this process?"

```
I. Skybox / Wiz / Prisma / CSPM tools
II. GitHub Actions / Jenkins / GitLab CI
III. ServiceNow / Jira / CMDB
IV. Homegrown scripts / manual
V. None / just CLI
```

**F-type Mapping:**
- I only → F1 (Ecosystem trap)
- II only → F2/F1 (Operator with CI/CD)
- III only → F7 (Organizational)
- IV/V → F4/F6 (Methodology-driven or feature extractor)
- Multiple → F1+F7 hybrid (highest risk of hybrid failure)

---

### Q5: Adoption Latency

**Question:** "If a better tool existed for this, how long would realistic adoption take?"

```
alpha. Immediately (personal decision)
beta. Weeks (pilot with team)
gamma. Months (requires process change)
delta. Unlikely / depends on team buy-in
```

**F-type Mapping:**
- alpha → Low adoption friction (not F2/F7)
- beta → F6 (Feature-focused)
- gamma → F2 (Workflow inertia)
- delta → F7 (Political buy-in) with high confidence

## 2. F-Type Prior Calculator

### Scoring Matrix

```python
@dataclass
class FTypePrior:
    """Predict F-type distribution from screener answers."""

    f1_probability: float
    f2_probability: float
    f3_probability: float
    f4_probability: float
    f5_probability: float
    f6_probability: float
    f7_probability: float

    primary_f_type: str
    secondary_f_type: str | None
    confidence: float
    hybrid_risk: bool  # True if multiple F's > 0.3


def compute_f_type_prior(
    q1: str,
    q2: str,
    q3: str,
    q4: list[str],
    q5: str,
) -> FTypePrior:
    """
    Compute F-type prior from screener responses.
    Used for batch stratification, not session-level decision.
    """

    scores = {"F1": 0, "F2": 0, "F3": 0, "F4": 0, "F5": 0, "F6": 0, "F7": 0}

    # Q1: Primary workflow (weight: 0.3)
    q1_weights = {
        "A": {"F5": 0.8, "F4": 0.1, "F6": 0.1},
        "B": {"F2": 0.5, "F1": 0.4, "F6": 0.1},
        "C": {"F4": 0.4, "F6": 0.4, "F3": 0.2},
        "D": {"F4": 0.5, "F3": 0.3, "F2": 0.2},
        "E": {"F1": 0.5, "F7": 0.4, "F2": 0.1},
    }
    for f, w in q1_weights[q1].items():
        scores[f] += w * 0.3

    # Q2: Where caught (weight: 0.2)
    q2_weights = {
        "a": {"F1": 0.7, "F2": 0.3},
        "b": {"F4": 0.6, "F2": 0.3, "F3": 0.1},
        "c": {"F5": 0.8, "F4": 0.1, "F6": 0.1},
        "d": {"F4": 0.4, "F6": 0.4, "F2": 0.2},
        "e": {"F3": 0.4, "F2": 0.4, "F7": 0.2},
    }
    for f, w in q2_weights[q2].items():
        scores[f] += w * 0.2

    # Q3: System of record (weight: 0.25)
    q3_weights = {
        "1": {"F7": 0.6, "F1": 0.2, "F2": 0.2},
        "2": {"F7": 0.7, "F1": 0.2, "F2": 0.1},
        "3": {"F2": 0.5, "F4": 0.3, "F3": 0.2},
        "4": {"F1": 0.6, "F2": 0.3, "F6": 0.1},
        "5": {"F3": 0.4, "F2": 0.4, "F7": 0.2},
    }
    for f, w in q3_weights[q3].items():
        scores[f] += w * 0.25

    # Q4: Tooling (weight: 0.15)
    if "IV" in q4 or "V" in q4:
        scores["F4"] += 0.15
        scores["F6"] += 0.1
    if "I" in q4:
        scores["F1"] += 0.2
    if "II" in q4:
        scores["F2"] += 0.15
        scores["F1"] += 0.1
    if "III" in q4:
        scores["F7"] += 0.15
    if len(q4) >= 3:
        scores["F1"] += 0.1
        scores["F7"] += 0.1

    # Q5: Adoption latency (weight: 0.1)
    q5_weights = {
        "alpha": {"F6": 0.3, "F4": 0.2},  # Low friction
        "beta": {"F6": 0.4, "F1": 0.2},   # Feature focused
        "gamma": {"F2": 0.5, "F7": 0.2},  # Inertia
        "delta": {"F7": 0.6, "F2": 0.2},  # Political
    }
    for f, w in q5_weights[q5].items():
        scores[f] += w * 0.1

    # Normalize and find primary/secondary
    total = sum(scores.values())
    if total > 0:
        normalized = {k: v / total for k, v in scores.items()}
    else:
        normalized = scores

    sorted_f = sorted(normalized.items(), key=lambda x: x[1], reverse=True)
    primary = sorted_f[0][0]
    secondary = sorted_f[1][0] if sorted_f[1][1] > 0.3 else None

    # Hybrid risk: multiple F's > 0.3
    hybrid_risk = sum(1 for _, v in sorted_f if v > 0.3) >= 2

    confidence = sorted_f[0][1]  # How confident are we in primary

    return FTypePrior(
        f1_probability=normalized["F1"],
        f2_probability=normalized["F2"],
        f3_probability=normalized["F3"],
        f4_probability=normalized["F4"],
        f5_probability=normalized["F5"],
        f6_probability=normalized["F6"],
        f7_probability=normalized["F7"],
        primary_f_type=primary,
        secondary_f_type=secondary,
        confidence=confidence,
        hybrid_risk=hybrid_risk,
    )
```

## 4. Screener Calibration Triggers

→ Stop recruiting auditors
→ Redirect to DevOps/platform channels

**If F3 > 30% of batch:**
→ Increase follow-up probe frequency
→ F3 users need explicit engagement strategy

**If F1+F7 hybrid > 50%:**
→ Expect longer adoption cycles
→ Plan for technical + organizational interventions

**If F4 (Methodology) < 10%:**
→ Screener may be filtering skeptics

## 7. F-Type Prior Interpretation Guide

### High Confidence Predictions (≥0.7)

```
Q1=A + Q2=c + Q3=1/2 → F5 (Compliance Auditor)
Q1=B + Q2=a + Q3=4 → F1 (Ecosystem Operator)
Q1=E + Q3=1/2 + Q5=delta → F7 (Political Pragmatist)
```

### Ambiguous Predictions (<0.5 confidence)

```
Q1=C + Q2=d + Q3=3 + Q5=beta → F4 vs F6 ambiguity
→ Need session to determine: methodology questions or feature interest?

Q1=D + Q2=e + Q3=5 → F3 (Silent) or F2 (Inertia)
→ Both have similar signals — session will disambiguate
```

### Hybrid Risk Detection

```
Multiple high signals in same user:
- Q4=I + Q3=1 + Q5=delta → F1+F7 hybrid (highest risk)
- Q4=II + Q4=III + Q2=a → F1+F2 hybrid (CI/CD + CMDB)
- Q1=A + Q1=E → Mixed role (auditor + platform lead)
```
