# ConfigGuard v1.3 — Decision Reality Alignment

**Status**: Production-Ready
**Version**: v1.3
**Date**: 2026-05-30
**Purpose**: Fix decision contract to handle representation sensitivity, hidden state, and multi-axis dependencies

---

## 0. What SAUS v3 Revealed

SAUS v3 found 3 structural failures, not random errors:

### Failure 1: Representation Sensitivity (F5)

**Problem:** Same real state → different decisions based on material variant shown.

**Example:** Auditor with standard material → NO-GO. Same auditor with B-auditor material → GO.

**Root cause:** Decision contract consumes raw material, not normalized evidence.

### Failure 2: Hidden State (F3)

**Problem:** Silent user = unobservable latent adoption state.

**Example:** Zero signals + H1 pass → treated as CONDITIONAL. But silent might be best adopter.

**Root cause:** System assumes "absence of signal = neutral state". Reality: absence = unknown.

### Failure 3: Dependency Coupling (F1 + F7)

**Problem:** Ecosystem (F1) and policy (F7) collapsed into single CONDITIONAL.

**Example:** "Has Skybox + needs manager approval" = same single constraint as "just thinking about it".

**Root cause:** Decision space not factorized. Real adoption has independent technical and organizational constraints.

## 1. Three State Dimensions

### v1.2 Problem

```
v1.2 treated all failures as single-dimensional:
  GO → YES/NO/CONDITIONAL

But CONDITIONAL was an invalid catch-all for:
  - Material not provided
  - Latent state unknown
  - Multiple unresolved constraints
```

### v1.3 Solution

```
v1.3 introduces 3 independent state dimensions:

Dimension 1: Evidence Quality
  - CANONICAL_EVIDENCE (CEF provided)
  - INCOMPLETE_EVIDENCE (CEF not provided)

Dimension 2: Observable Behavior
  - ACTIVE_SIGNAL (adoption signals present)
  - SILENT_UNKNOWN (no signals, H1 pass, but state unknown)
  - ACTIVE_REJECTION (warning signals dominate)

Dimension 3: Adoption Constraints
  - TECHNICAL_SATISFIED (integration/feature requirements met)
  - TECHNICAL_BLOCKED (integration/feature gap)
  - ORGANIZATIONAL_SATISFIED (approval/buy-in obtained)
  - ORGANIZATIONAL_BLOCKED (approval/buy-in required)
```

## 2. Canonical Evidence Form (CEF)

### Purpose

Normalize all material variants to single evidence format before decision contract.

### CEF Structure

```python
@dataclass
class CanonicalEvidenceForm:
    """
    All materials (standard/auditor/operator/skeptic)
    must be converted to CEF before decision.
    """

    finding_id: str                          # Unique finding ID
    raw_finding: str                        # Original finding text

    # Control mapping (optional — present in B-auditor)
    control_mapping: dict | None
    # {
    #     "cis": ["CIS-2.4"],
    #     "nist": ["IA-2"],
    #     "evidence": "line 42: snmp-server community public RO"
    # }

    # Severity (always present)
    severity_raw: str                       # CRITICAL/HIGH/MEDIUM/LOW
    severity_score: int                      # 0-100

    # Evidence chain
    evidence_chain: list[str]                # ["line 42", "snmp-server community public RO"]
    resource_id: str | None                  # Which resource is affected
    resource_type: str | None                # snmp / vty / interface / etc

    # Behavioral signals attached
    h1_score: int                            # /4
    h2_score: int                             # /4
    verbatim_key_phrases: list[str]          # Critical verbatim quotes

    @property
    def is_complete(self) -> bool:
        """CEF is complete if all required fields populated."""
        return (
            self.finding_id is not None
            and self.severity_raw is not None
            and self.severity_score is not None
            and self.h1_score is not None
        )
```

### CEF Conversion Rules

```
Material B-standard → CEF:
  - control_mapping: None (not available)
  - All other fields: populated

Material B-auditor → CEF:
  - control_mapping: populated from finding
  - All other fields: populated

Material B-operator → CEF:
  - control_mapping: None (not relevant)
  - All other fields: populated

Material B-skeptic → CEF:
  - control_mapping: None
  - All other fields: populated
  - verbatim_key_phrases: capture skeptic questions
```

### Decision Contract Rule

```
RULE: Decision contract ONLY consumes CEF, never raw material.

Before applying decision contract:
  1. Convert material to CEF
  2. If CEF.is_complete: proceed with decision
  3. If CEF.control_mapping is None AND user_type == Auditor:
     → CEF is INCOMPLETE_EVIDENCE
     → Flag as representation gap, not adoption failure
```

## 3. Latent State Probe

### Purpose

Detect silent adoption (F3) which is invisible in session.

### The F3 Problem

```
F3 (Silent) was treated as:
  - Zero signals + H1 pass
  - → CONDITIONAL by default
  - → Don't count toward or against

But SAUS v3 revealed:
  - Silent might be best adopter (adopted without telling you)
  - Silent might be rejected (never intended to use)
  - You CAN'T tell from session alone
```

### Latent State Classification

```python
@dataclass
class LatentState:
    """
    F3 (Silent) must be resolved into specific latent state.
    """

    # Three possible latent states
    LATENT_ADOPTER: str = "LATENT_ADOPTER"       # Will use it, didn't say
    LATENT_REJECTOR: str = "LATENT_REJECTOR"     # Won't use it, didn't object
    LATENT_UNDETERMINED: str = "LATENT_UNDETERMINED"  # Cannot determine

    # Probe method used
    probe_method: str | None  # "follow_up" / "task_based" / "unknown"
    probe_response: str | None  # "used" / "not_used" / "no_response"
    probe_date: str | None      # Date probe was sent
    probe_response_date: str | None  # Date response received
```

### Probe Protocol (Mandatory for F3)

```
IF adoption_signals == 0 AND h1_score >= 3/4:
  THEN:
    1. Classify state as LATENT_UNDETERMINED
    2. Flag session for mandatory follow-up
    3. Send probe within 48 hours

Probe methods (in priority order):
  1. Task-based: "Did you try ConfigGuard on a real config this week?"
     → If yes: LATENT_ADOPTER
     → If no: LATENT_REJECTOR or LATENT_UNDETERMINED

  2. Follow-up email: "Curious if you had a chance to try it?"
     → If used: LATENT_ADOPTER
     → If not: LATENT_UNDETERMINED (need more time)

  3. No response after 2 attempts: LATENT_UNDETERMINED (permanently unknown)
```

### Decision Contract Rule for Latent State

```
RULE: LATENT_UNDETERMINED blocks GO decision.

GO if:
  - active_signal OR latent_state == LATENT_ADOPTER
  - NOT: latent_state == LATENT_UNDETERMINED

LATENT_REJECTOR → NO-GO
LATENT_ADOPTER → Count toward GO
LATENT_UNDETERMINED → INSUFFICIENT_SIGNAL (new state)
```

## 4. Dependency Factorization

### Purpose

Separate technical and organizational constraints that were coupled in CONDITIONAL.

### v1.2 Problem

```
CONDITIONAL GO was single state for:
  - F1 (ecosystem gap)
  - F2 (workflow inertia)
  - F7 (political buy-in)

But these are independent constraints:
  - Ecosystem (F1): Technical — can ConfigGuard integrate?
  - Workflow (F2): Organizational — will org change?
  - Political (F7): Organizational — who has veto power?
```

### v1.3 Solution

```python
@dataclass
class AdoptionConstraints:
    """
    Technical and organizational constraints are independent.
    """

    # Technical constraints
    integration_required: bool      # Needs ServiceNow/CMDB/etc
    integration_available: bool      # Integration exists
    feature_required: list[str]     # Specific features needed
    feature_available: list[str]     # Specific features exist

    # Organizational constraints
    approval_required: bool         # Manager/team approval needed
    approval_obtained: bool         # Approval received
    policy_required: list[str]       # Policy compliance needed
    policy_satisfied: bool          # Policy compliance confirmed

    @property
    def technical_satisfied(self) -> bool:
        """All technical constraints must be satisfied."""
        if self.integration_required and not self.integration_available:
            return False
        # Feature constraint: all required features must be available
        return all(f in self.feature_available for f in self.feature_required)

    @property
    def organizational_satisfied(self) -> bool:
        """All organizational constraints must be satisfied."""
        if self.approval_required and not self.approval_obtained:
            return False
        if self.policy_required and not self.policy_satisfied:
            return False
        return True
```

### Decision Rules for Dependencies

```
GO requires BOTH:
  technical_satisfied == True
  organizational_satisfied == True

NO-GO if:
  technical_satisfied == False OR
  organizational_satisfied == False

Note: CONDITIONAL GO is no longer a valid state.
  - Technical blocked → Technical gap (address in roadmap)
  - Organizational blocked → Org constraint (not product failure)
```

### F1 + F7 Factorization Example

```
Before (v1.2):
  User has Skybox (F1) + needs manager approval (F7)
  → CONDITIONAL GO (single state)

After (v1.3):
  User has Skybox + needs ServiceNow + needs manager approval
  → Technical: integration_required=True, integration_available=False
  → Organizational: approval_required=True, approval_obtained=False
  → Both unsatisfied → NO-GO
  → But: Different reasons for each constraint
  → Technical gap → product roadmap item
  → Organizational gap → not product failure
```

## 5. New Decision State: INSUFFICIENT_SIGNAL

### Purpose

Replace CONDITIONAL GO with explicit "cannot decide" state.

### Why CONDITIONAL was Invalid

```
CONDITIONAL GO implied:
  - We're not sure, but maybe
  - Partial adoption likely
  - Some signals present

But CONDITIONAL masked 3 different situations:
  1. Material not provided → Representation gap
  2. Latent state unknown → F3 unresolved
  3. Dependencies unclear → Factorization needed
```

### INSUFFICIENT_SIGNAL State

```python
class DecisionState(str, Enum):
    """
    v1.3 replaces CONDITIONAL with explicit decision states.
    """

    GO = "GO"                                    # Ready for field
    NO_GO = "NO_GO"                              # Not ready
    INSUFFICIENT_SIGNAL = "INSUFFICIENT_SIGNAL"  # Cannot decide yet
```

### When INSUFFICIENT_SIGNAL Applies

```
INSUFFICIENT_SIGNAL applies when:

1. Evidence gap:
   - CEF.is_complete == False
   - AND user_type requires complete evidence
   - Example: Auditor without control mapping

2. Latent state:
   - latent_state == LATENT_UNDETERMINED
   - AND follow-up probe not completed
   - Example: F3 without follow-up

3. Dependency unresolved:
   - adoption_constraints.technical_satisfied == unknown
   - OR adoption_constraints.organizational_satisfied == unknown
   - Example: F1+F7 hybrid without factorization

4. DRIFT rate > 40%:
   - Taxonomy insufficient
   - Cannot classify reliably
```

### INSUFFICIENT_SIGNAL Handling

```
INSUFFICIENT_SIGNAL is terminal state, not transitional.

Rule: INSUFFICIENT_SIGNAL requires specific resolution action.

Resolution path per cause:
  1. Evidence gap → Provide CEF, re-evaluate
  2. Latent state → Complete follow-up probe, re-evaluate
  3. Dependency unresolved → Factorize constraints, re-evaluate
  4. DRIFT > 40% → Redesign taxonomy, restart testing

INSUFFICIENT_SIGNAL does NOT become GO or NO-GO without explicit resolution.
```

## 6. v1.3 Decision Engine

### Input → Output Mapping

```
INPUTS:
  - CEF (normalized evidence)
  - behavioral_signals (v1.1 metrics)
  - latent_state_probe (for F3)
  - adoption_constraints (for F1/F2/F7)

OUTPUT:
  - GO: Ready for field deployment
  - NO_GO: Not ready, address specific failures
  - INSUFFICIENT_SIGNAL: Cannot decide, resolve specific gaps
```

### Decision Flow

```python
def compute_decision_v1_3(
    cef: CanonicalEvidenceForm,
    latent_state: LatentState | None,  # None if not F3
    adoption_constraints: AdoptionConstraints,
    drift_rate: float,
) -> DecisionState:
    """
    v1.3 decision engine.
    """

    # Step 1: Evidence check
    if not cef.is_complete:
        if cef.control_mapping is None and cef.user_type == "Auditor":
            return DecisionState.INSUFFICIENT_SIGNAL
            # Reason: "Evidence gap — control mapping required for Auditor"
        else:
            return DecisionState.INSUFFICIENT_SIGNAL
            # Reason: "Evidence incomplete"

    # Step 2: Latent state check
    if latent_state is not None:
        if latent_state.state == LatentState.LATENT_UNDETERMINED:
            return DecisionState.INSUFFICIENT_SIGNAL
            # Reason: "Latent state unknown — follow-up probe required"
        elif latent_state.state == LatentState.LATENT_REJECTOR:
            return DecisionState.NO_GO
            # Reason: "Latent rejection confirmed"

    # Step 3: Dependency check
    if not adoption_constraints.technical_satisfied:
        return DecisionState.INSUFFICIENT_SIGNAL
        # Reason: "Technical constraints not met"

    if not adoption_constraints.organizational_satisfied:
        return DecisionState.INSUFFICIENT_SIGNAL
        # Reason: "Organizational constraints not met"

    # Step 4: DRIFT check
    if drift_rate > 0.40:
        return DecisionState.INSUFFICIENT_SIGNAL
        # Reason: "Taxonomy insufficient — DRIFT rate > 40%"

    # Step 5: GO decision
    if (
        cef.h1_score >= 4  # H1 pass rate 100%
        and latent_state is not None
        and latent_state.state == LatentState.LATENT_ADOPTER
    ):
        return DecisionState.GO

    return DecisionState.NO_GO
```
