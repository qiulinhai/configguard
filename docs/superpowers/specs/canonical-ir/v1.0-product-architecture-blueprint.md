# ConfigGuard v1.0 — Product Architecture Blueprint

**Status**: Design Draft
**Version**: v1.0
**Date**: 2026-05-30
**Purpose**: Define the product architecture for enterprise-grade security intelligence

---

## 0. Executive Summary

### Current State (v0.4)
ConfigGuard is a **Security Semantic Intelligence Engine (SSIE)** with:
- Multi-vendor config parsing (Cisco IOS, Linux SSH, K8s)
- Canonical IR v1 (vendor-neutral semantic model)
- Security Knowledge Graph (cross-resource relationships)
- Graph Rule Engine (attack path inference)
- Composite Risk Engine v0.4 (explainable multi-factor scoring)

### Target State (v1.0)
ConfigGuard becomes a **Security Intelligence Platform** with:
- Enterprise-grade API (REST + streaming)
- Plugin system for vendors/rules/policies
- CI/CD integration (git diff → incremental audit)
- Policy packs (CIS/NIST/ISO compliance)
- Multi-tenant deployment
- SaaS + on-prem options

### Product Vision
> ConfigGuard answers: "What is my attack surface, how will I be attacked, and what should I fix first?"

      status: string     # FAIL | WARN | PASS
      evidence: string
      block_name: string
      remediation: string
      risk_contribution: number  # How much this adds to risk score
  attack_paths:
    - path_id: string
      path_length: number
      entry_point: string
      terminal_node: string
      risk_score: number
      relationship_chain: string
  composite_score: number           # 0-100
  risk_level: string                # CRITICAL | HIGH | MEDIUM | LOW | INFO
  risk_factors:
    - name: string

    def supported_resource_types(self) -> list[str]:
        """List of resource_types this adapter can produce."""
        raise NotImplementedError

    def parse(self, raw_config: str, metadata: dict | None = None) -> list[CanonicalResource]:
        """Parse vendor config into Canonical IR."""
        raise NotImplementedError

    def validate_config(self, raw_config: str) -> tuple[bool, str | None]:
        """Validate config syntax before parsing."""
        raise NotImplementedError

## 5. CI/CD Integration

### 5.1 Incremental Diff Engine

```python
# configguard/ci/incremental.py
class IncrementalAuditEngine:
    """Audit only changed portions of configuration."""

    def __init__(self, adapters: list[VendorAdapter]):
        self.adapters = adapters

    def diff_configs(
        self,
        old_config: str,
        new_config: str,
        vendor: str
    ) -> list[ConfigChange]:
        """Identify what changed between two configs."""
        ...

    def audit_changes(
        self,
        old_config: str,
        new_config: str,
        vendor: str,
        rules_dir: str
    ) -> AuditResult:
        """Run audit only on changed sections."""
        changes = self.diff_configs(old_config, new_config, vendor)

        # Run targeted audit on changed areas
        targeted_findings = []
        for change in changes:
            findings = self._audit_change(change, old_config, new_config, rules_dir)
            targeted_findings.extend(findings)

        return AuditResult(
            findings=targeted_findings,
            changes_detected=len(changes),
            risk_delta=self._compute_risk_delta(findings),
            metadata={
                "change_types": [c.type for c in changes],
                "affected_resources": [c.resource_id for c in changes],
            }
        )
```

### 5.3 CI/CD Usage Examples

```yaml
# GitHub Actions Example
# .github/workflows/security-audit.yml
name: Security Config Audit
on:
  push:
    branches: [main, develop]
  pull_request:
    paths:
      - '**/config/**'
      - '**/*.cfg'
      - '**/*.conf'
      - '!**/*.example'

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
        with:
          fetch-depth: 0

      - name: Run ConfigGuard Audit
        uses: configguard/ci-action@v1
        with:
          api-key: ${{ secrets.CONFIGGUARD_API_KEY }}
          mode: incremental
          policy-pack: cis_enterprise
          fail-on-level: HIGH

      - name: Comment PR
        if: github.event_name == 'pull_request'
        uses: configguard/pr-comment@v1
        with:
          audit-id: ${{ steps.audit.outputs.audit_id }}
```

## 9. Technical Decisions

### ADJ-001: API Framework
**Decision**: Use FastAPI
**Rationale**: Auto-generates OpenAPI docs, async support, Pydantic validation

### ADJ-002: Database
**Decision**: PostgreSQL
**Rationale**: Relational data (tenants, audit history), JSON support for findings

### ADJ-003: Caching
**Decision**: Redis
**Rationale**: Audit result caching, session management, rate limiting

### ADJ-004: Container Platform
**Decision**: Docker + Kubernetes
**Rationale**: Standard deployment, self-hosted option, horizontal scaling

### ADJ-005: Plugin Language
**Decision**: Python only (v1.0)
**Rationale**: ConfigGuard core is Python, keep plugin development simple
