# ConfigGuard v1.0 — CLI + UX Design

**Status**: Design Draft
**Version**: v1.0
**Date**: 2026-05-30
**Purpose**: Define the user-facing product interface — the CLI and output UX

---

## 0. Product Positioning

### Core Product Loop
```
User Action:      "I pushed a config change"
      ↓
ConfigGuard:     "Your attack surface changed"
      ↓
Output:          "Here's what happened and what to do"
```

### Product Principle
> ConfigGuard answers: "What changed, why does it matter, and what should I do?"

**Not**:
- A scanner that finds vulnerabilities
- A framework for engineers
- A configuration database

**Yes**:
- A security intelligence tool that explains impact
- A daily-driver for security teams
- An audit loop that fits into existing workflows

## 1. Command Design

### 1.1 Core Commands

```
configguard diff <old> <new>    # Compare two configs, show drift
configguard audit <config>     # Full audit of single config
configguard check <config>     # Evaluate against policy pack
configguard explain <audit>    # Human-readable audit explanation
```

### 1.2 `diff` Command (Killer Feature)

```bash
# Basic usage
configguard diff old_router.cfg new_router.cfg

# With policy pack
configguard diff old.cfg new.cfg --policy cis

# CI mode (exit code for automation)
configguard diff old.cfg new.cfg --policy cis --ci
```

**Output — 3 Core Lines:**
```
❗ SECURITY DRIFT DETECTED — Attack surface +37%

[CRITICAL] SNMP v2c public community exposed
  - Source: new line 42 added
  - Network exposure: internet-facing mgmt plane
  - Fix: Change community or disable SNMP

[WARNING] Telnet enabled alongside SSH  
  - Source: new line 55 modified
  - Risk: Dual access = higher exposure
  - Fix: Disable telnet

📊 Risk Delta: +37 → +74 (HIGH)
📋 Run `configguard explain <audit_id>` for details
```

**Exit Codes:**
- 0: No drift or drift only in INFO severity
- 1: Drift with LOW/MEDIUM severity
- 2: Drift with HIGH/CRITICAL severity

### 1.3 `audit` Command

```bash
# Basic usage
configguard audit router.cfg

# Full analysis with graph
configguard audit router.cfg --full

# Specific vendor
configguard audit router.cfg --vendor cisco_ios

# Output formats
configguard audit router.cfg --format table   # default
configguard audit router.cfg --format json     # for automation
configguard audit router.cfg --format markdown # for reports
```

**Output — 3 Core Lines:**
```
🔍 CONFIGGUARD AUDIT COMPLETE

📊 Risk Score: 74/100 (HIGH)
🔴 Critical: 2 | 🟠 High: 3 | 🟡 Medium: 1 | 🟢 Low: 0

Top Risk:
  - SNMP v2c with public community (CRITICAL)
  - Telnet enabled on VTY (HIGH)
  - HTTP server enabled (HIGH)

📋 Run `configguard explain abc123` for remediation steps
```

### 1.4 `check` Command (Policy Evaluation)

```bash
# Evaluate against CIS benchmark
configguard check router.cfg --policy cis

# Check against NIST
configguard check router.cfg --policy nist80053

# Custom policy pack
configguard check router.cfg --policy ./my_policy.yaml
```

**Output:**
```
📋 CIS BENCHMARK EVALUATION

Total Controls: 47
  ✓ Compliant: 38
  ⚠️ Partial: 4
  ❌ Non-compliant: 5

Coverage Score: 81%

Non-Compliant Controls:
  - CIS-1.1: AAA not configured (CRITICAL)
  - CIS-2.2: Telnet enabled (HIGH)
  - CIS-3.5: SNMP defaults not changed (HIGH)
```

### 1.5 `explain` Command (Deep-dive)

```bash
configguard explain abc123

# Explain specific finding
configguard explain abc123 --finding CISCO-SNMP-001

# Generate remediation script
configguard explain abc123 --fix
```

**Output:**
```
🔍 FINDING: SNMP v2c Public Community

Severity: CRITICAL
Category: network.snmp
Status: FAIL

📖 What This Means:
  Your device has SNMP version 2c enabled with the default "public" 
  community string. This allows anyone with network access to:
  - Read your entire running configuration
  - Identify all network devices and their addresses
  - Map your internal network topology

🗺️ Attack Path:
  Internet → SNMP (port 161) → Device Config → Full Network Map

💣 Risk Explanation:
  SNMP v2c transmits community strings in plaintext. An attacker 
  on the same network can capture these with packet sniffing and 
  gain full device visibility.

✅ Recommended Fix:
  1. Change community string: snmp-server community <random> RO
  2. Restrict SNMP access: snmp-server community <secret> RO 10.0.0.0/8
  3. Consider migrating to SNMPv3 with authPriv

🔧 Automated Fix (review before applying):
  configure
  no snmp-server community public RO
  snmp-server community <your-secure-string> RO 10.0.0.0/8
  end
```

## 2. Output Design

### 2.1 Output Principles

| Principle | Implementation |
|-----------|---------------|
| **Actionable first** | Every finding has a fix |
| **Risk explains itself** | "What" + "Why" + "Fix" in one view |
| **Progressive disclosure** | 3 lines default, `--full` for everything |
| **Machine-readable available** | `--format json` always works |

### 2.2 Output Layers

```
Layer 1: Summary (default)
  → 3 lines: risk score + top 3 issues + action

Layer 2: Findings
  → All findings with severity + one-line explanation
  → Triggered by: --verbose or output to TTY

Layer 3: Full Report
  → Complete audit with attack paths + graph
  → Triggered by: --full or --format json
```

### 2.3 Visual Output Style

```
Color Coding:
  🔴 CRITICAL / score >= 85  (red)
  🟠 HIGH     / score >= 65  (orange)
  🟡 MEDIUM   / score >= 40  (yellow)
  🟢 LOW      / score >= 20  (green)
  🔵 INFO     / score < 20   (blue)

Risk Delta Indicators:
  ✅ Risk reduced (green)
  ❌ Risk increased (red)
  ⚠️ No significant change (yellow)
```

### 2.4 Table Output Format

```
┌─────────────────────────────────────────────────────────────────────┐
│ ConfigGuard Audit — router.cfg                                       │
├─────────────────────────────────────────────────────────────────────┤
│ 🔴 CRITICAL  │ SNMP v2c public community exposed                  │
│ 🟠 HIGH      │ Telnet enabled on VTY access                       │
│ 🟠 HIGH      │ HTTP server enabled without SSL                    │
│ 🟡 MEDIUM    │ SSH password authentication enabled                │
│ 🟡 MEDIUM    │ AAA missing backup authentication                  │
└─────────────────────────────────────────────────────────────────────┘
```

## 3. UX Flows

### 3.1 Daily Usage Flow (Security Team)

```
Morning: Security Review
  $ configguard diff main.cfg pre-prod.cfg --ci
  ❗ 2 security changes detected
  
  $ configguard explain abc123 --finding CISCO-SNMP-001
  [Reads fix instructions, decides to fix]
  
  $ configguard audit post-fix.cfg
  📊 Risk Score: 31 (down from 74)
  ✅ SNMP exposure resolved
```

### 3.2 CI/CD Integration Flow

```yaml
# .github/workflows/config-audit.yml
name: Config Security Audit
on:
  pull_request:
    paths:
      - 'configs/**'

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - name: Run ConfigGuard diff
        run: |
          git diff HEAD~1 -- configs/ > changes.diff
          configguard diff \
            $(git show HEAD~1:configs/router.cfg) \
            $(git show HEAD:configs/router.cfg) \
            --ci --policy cis --fail-on HIGH

      - name: Comment PR
        if: failure()
        uses: configguard/pr-comment@v1
        with:
          audit_output: ${{ steps.audit.outputs.summary }}
```

### 3.3 Remediation Flow

```
Finding detected
    ↓
User runs: configguard explain <id> --fix
    ↓
ConfigGuard shows:
  1. Manual fix steps
  2. Generated CLI commands (review only)
  3. Safety check (will this break connectivity?)
    ↓
User applies fix
    ↓
User runs: configguard audit post-fix.cfg
    ↓
Risk score drops → ✅ Resolved
```

## 4. CLI Flags Design

### 4.1 Global Flags

```bash
--format, -f     # Output format: table|json|markdown (default: table)
--verbose, -v    # Verbose output (show all findings)
--quiet, -q      # Quiet mode (summary only)
--ci             # CI mode (exit code based on severity)
--no-color      # Disable colored output
--output, -o     # Output file path
--config         # Config file for settings
```

### 4.2 Per-Command Flags

```bash
# diff
configguard diff <old> <new> --policy --ci --vendor

# audit
configguard audit <config> --full --vendor --format

# check
configguard check <config> --policy --format

# explain
configguard explain <id> --finding --fix --format
```

### 4.3 Environment Variables

```bash
CONFIGGUARD_API_KEY      # For SaaS mode
CONFIGGUARD_RULES_DIR    # Custom rules directory
CONFIGGUARD_POLICY_DIR    # Policy packs directory
CONFIGGUARD_NO_COLOR     # Disable colors
```

## 5. User Personas

### 5.1 Security Analyst (Primary User)

**Persona**: Reviews config changes daily
**Wants**: "What changed, why is it risky, what do I do?"
**Tools**: CLI + Slack notifications + PR comments

### 5.2 Network Engineer (Secondary User)

**Persona**: Makes config changes, needs approval
**Wants**: "Is my change safe?"
**Tools**: CLI before push + email summary

### 5.3 Compliance Auditor (Report Consumer)

**Persona**: Reviews audit history for compliance
**Wants**: "What are our critical risks and when were they fixed?"
**Tools**: Web dashboard + CSV exports + PDF reports

## 6. Error Handling UX

### 6.1 User-Friendly Errors

```bash
# Invalid config
$ configguard audit malformed.cfg
❌ Parse Error: Invalid Cisco IOS syntax at line 42
   Expected: interface <name> or line <type>
   Run with --verbose for full trace

# Unsupported vendor
$ configguard audit config.txt --vendor juniper
❌ Vendor "juniper" not supported in v1.0
   Supported vendors: cisco_ios, linux_ssh, kubernetes
   Use --vendor auto for automatic detection

# Empty config
$ configguard audit empty.cfg
ℹ️  No configuration detected
   This file appears to be empty or contains only comments
```

### 6.2 Automation Errors

```bash
# CI mode with error
$ configguard diff old.cfg new.cfg --ci
Output:
  ❌ SECURITY DRIFT: +37 risk delta
  Exit code: 2 (HIGH/CRITICAL severity)

# JSON output for parsing
$ configguard audit router.cfg --format json > audit.json
# (JSON always valid, even on errors)
```

## 7. Exit Codes

| Code | Meaning | CI Behavior |
|------|---------|-------------|
| 0 | No security issues | ✅ Pass |
| 1 | LOW/MEDIUM only | ⚠️ Warn |
| 2 | HIGH/CRITICAL | ❌ Fail |
| 3 | Parse/Config error | ❌ Fail |
| 4 | System error | ❌ Fail |

## 9. Summary

### The 3 Core Commands

| Command | Purpose | Output |
|---------|---------|--------|
| `diff` | What changed? | Risk delta + changes |
| `audit` | What are the risks? | Risk score + findings |
| `explain` | What do I do? | Fix steps + attack path |

### Product Principle

> **"3 lines to understand, 3 steps to fix"**

Every user interaction should answer these questions in order:
1. **What changed?** (diff)
2. **Is it risky?** (audit score)
3. **What do I do?** (explain)
