# ConfigGuard v0.2 Release Notes

> **Version:** 0.2.0
> **Date:** 2026-05-29
> **Status:** Released

---

## Overview

v0.2 introduces the **Signal Layer** — a semantic abstraction between configuration parsing and rule evaluation. This is an architecture addition that enables future reasoning capabilities while maintaining full backward compatibility with v0.1.

---

## What's New

### Signal Layer Architecture

A new semantic layer that normalizes configuration observations into canonical Signals:

```
Config → Parser → ConfigIR → Signal Extractor → Signals
                                              ↓
                              ┌───────────────┴───────────────┐
                              ↓                               ↓
                       v0.1 Legacy Rules              v0.2 Signal Rules
                              ↓                               ↓
                              └───────────────┬───────────────┘
                                              ↓
                                      Findings (Unified)
```

### Signal Types Supported

| Signal Type | Source | Values |
|-------------|--------|--------|
| `transport_input` | VTY line commands | telnet, ssh |
| `auth_method` | VTY line commands | local |
| `interface_state` | Interface blocks | up, shutdown |
| `interface_description` | Interface blocks | present, missing |
| `aaa_enabled` | Global config | true, false |
| `http_server` | Global config | enabled, disabled |
| `snmp_version` | Global config | v2c |
| `snmp_community` | Global config | public, private, community123 |
| `syslog_host` | Global config | configured |
| `ntp_server` | Global config | configured |

### Context Builder

Semantic grouping of signals for rule evaluation. Groups related signals (e.g., all SNMP communities) into single contexts so rules evaluate once against aggregated evidence.

```
Signals → Context Builder → SignalContexts → RuleEngine → Findings
                    ↑
            Semantic grouping by rule-relevant dimensions
```

### Deduplication Fix

Signal deduplication now correctly preserves all distinct global signal values using `(type, context, value)` triple key — multiple SNMP communities (public, private, community123) are all preserved instead of collapsing to one.

---

## Backward Compatibility

v0.2 is fully backward compatible with v0.1:

- All existing YAML rules continue to work unchanged
- CLI interface unchanged
- Output schema unchanged
- v0.1 rules execute via legacy path, v0.2 signal rules execute via signal path
- Findings from both paths are merged and deduplicated
